# 产品备忘录

> 持续记录方向性判断。新条目放最上面，避免过期结论被当成现状。

## 2026-10-23 · 记忆与自进化

### 结论

> 记忆不是仓库，是**决策缓存**；自进化不是模型自改，是**资产管线**。

产品变聪明，不是记住更多，而是：

- 更快复用被验证过的决策
- 更少重复已知错误
- 更少打断用户
- 更少返工

### 记忆分层

```text
Working context   当前任务上下文 / checkpoint，不是长期记忆
Episodic          发生过什么：任务、决策、结果
Semantic          事实、偏好、团队约定
Procedural        怎么做：playbook、模板、检查清单
Evaluative        什么有效/无效：评分、review findings、失败原因
```

“聊过什么”属于 transcript；能进 prompt 的必须是经过筛选的记忆。

### 只学三类东西

1. **语义记忆**：偏好、约定、项目事实；带来源、时间、置信度、有效期。
2. **决策记忆**：为什么批准/拒绝、代价、谁拍板。比只记结论更有价值。
3. **程序记忆**：成功任务的步骤、工具顺序、检查清单；沉淀成可执行 playbook，不是散文。

### 写入记忆的三道门

```text
重复出现？    ≥2–3 次
影响决策？    会改变下一步行动
有证据？      来源、结果、置信度
```

三条都满足才晋级 `active`；否则只写 `proposed`。  
用户明确说“以后都这样”，可立即 active；其余先提案。

### 自进化闭环

```text
观察 → 诊断 → 提案 → 验证 → 晋级 → 监控 → 退休
```

可进化的资产：

- Memory entry
- Prompt 片段
- Task / team template
- Tool policy
- Playbook
- Evaluation case

规则：

- 默认 proposed，有证据才 active
- 版本化、来源、可回滚
- 高风险变更必须人确认
- 不允许 Agent 直接改自己的核心 prompt

### 记忆的敌人

不是遗忘，是污染：

- 网页/工具内容注入的假事实
- 一次例外被当成永久偏好
- 过期信息覆盖新信息
- 团队记忆被单个成员的单次观点污染
- 只增不减，prompt 越来越脏

需要：

- 来源与信任级别
- 过期 / supersede，不是删除
- 冲突解决：新证据、权威来源、用户确认
- 用户可查看、纠正、遗忘
- 成员只能 propose，Leader/用户 accept

### 组织学习

除了记事实，还要学：

- 这类任务需要几个人
- 哪种编制成功率高
- 哪个成员适合哪类任务
- 哪类任务必须加 verifier
- 哪类审批经常被拒绝

调整默认团队模板，而不是让用户每次自己配。

### 评估

“变聪明”的指标：

- 任务成功率
- 人工打断次数
- 返工率
- 从提问到决策的时间
- 成本 / token
- 记忆命中后是否真的有用
- 记忆纠错率 / 过期率

不是回答更流畅。

### 落地顺序

```text
P0  决策账本 + 团队评分卡
P1  带引用的检索 + proposed 记忆
P2  从成功任务提取 playbook
P3  按任务类型优化团队编制
P4  Prompt/模板 shadow 后灰度
```

### 反模式

- 全量对话 RAG
- 自动 capture 一切
- Agent 给自己打分并直接改 Prompt
- 记忆只增不删
- 用记忆替代上下文交接
- 用“记得多”冒充“变聪明”

### 一句话

> 记住少数真正影响决策的事，验证它，复用它，并在失效时忘掉它。
