## Findings

### F1 — `创建默认成员` shows a false "no provider/model" error before the catalog loads (medium)

Repro (deterministic):

1. Open 团队 → 新建团队.
2. Click **创建默认成员** within ~1 s of the dialog rendering.
3. Observe `当前没有可用的 Provider、模型、Agent Preset 或权限预设，无法创建默认成员。` and no member created (`15-member-template-created.png`, `20-member-created.png`).
4. Wait ~7 s, click **创建默认成员** again → succeeds, `所有助手 (1)` (`21-member-created-late.png`).

Root cause (read-only inspection): `createDefaultAssistant` reads the dialog's `catalog` from `useAgentTeamData`, which is fetched fire-and-forget (`void callAgentTeam('catalog.get')`). Until it resolves, `catalog === undefined` and the guard reports the terminal "no provider/model" message instead of a loading state. The message is also sticky (needs a re-click).

Verified in the same session: `catalog.get` returned `{xiaomi-token-plan-cn: [mimo-v2.6-flash, mimo-v2.6-pro]}` and the native model picker showed `MiMo-V2.6-Flash`, so the host did have a model.

Suggested fix direction: disable the button / show progress while `catalog === undefined`; only show that error when the catalog is loaded and genuinely empty.

### F2 — Clicking a team row or member row never opens the Leader session (high)

Repro:

1. Create a team (`e2e-alpha`, 1 member, Leader session `session-dc25ffa8-…` per `team.get`).
2. Click the team row → sidebar row highlights, **main pane stays on the native landing composer**, no session header, no error, no navigation (`35-team-page.png`, `36-after-team-click.png`).
3. Click the member row (`通用成员 / Leader`) → identical (`48-team-row-click-2.png`).
4. Manage team → **Reconnect** → close → click team row again → still nothing (`54-reconnect.png`, `55-after-reconnect-nav.png`).

Evidence that the data is fine: `team.get` returns a resolvable Leader with `sessionId: session-dc25ffa8-b48d-47a2-8daa-3f6ff17872ba`; network capture shows no session-open request after the click (only landing-asset traffic in the first trace). By contrast, opening the **assistant** DM row does render a conversation view (`45-dm-open.png`), so session rendering itself works.

Root cause candidate: `openTeamPage()` → `ctx.uiWorkspace.openSession(leaderSessionId)` is a silent no-op for this session, and the surrounding promise chain swallows errors (`.catch(() => undefined)`), so the failure is invisible to the user.

Impact: the shipped "team page / team main agent panel" entry point is unreachable from the sidebar; only the Manage dialog is reachable.

Impact: screen-reader/visible label mismatch and inconsistent language in a Chinese-default UI.

### F4 — Startup request amplification (low/medium)

One page mount issues 7 `team.list` POSTs (plus 3–4 each of `assistant.instance.*`, `assistant.list`, `catalog.get`) inside ~0.5 s (`06-api-probe.png` network trace). Each was 200 in ~30 ms, so no user-visible failure — but it is redundant load that also widened the F1 race window.

### F5 — Add member cannot be completed via UI (blocker for matrix 4c)

- `assistant.list` returns exactly **one** assistant (`通用成员`, `teamSelectable: true`). There is no second candidate.
- The `单聊` assistant created through 新建单聊助手 (`e2e-helper`) is **not** returned by `assistant.list` and is **not** offered by 添加助手; it works as a DM (`47-dm-reply.png`) but is invisible to team membership.
- Clicking **添加助手** opens a panel showing the existing member's config (`助手配置 / 通用成员 / xiaomi-token-plan-cn / mimo-v2.6-flash`) instead of a candidate list; `团队成员` stays `1 人` (`49`, `50`, `53`).

Result: adding a member is blocked without a template created elsewhere (设置 → 团队), which is outside this run's reachable UI. Recorded as blocked, not pass.

### F6 — Global overview / attention center not reachable (matrix 12)

`data-overview-region` elements (the overview component's stable hooks: `attention`, `global-overview`, `filters`) do not exist anywhere in the DOM while the Manage dialog's 成员/活动 tabs are open (`51-activity-tab.png`). The component is only mounted from team pages that F2 makes unreachable, so counts/filters/approvals could not be exercised.

- Restarted the isolated instance on the same port 3099 with `DSH_HOME=/tmp/dsh-e2e-home`; the auth token therefore rotated.

No product code, no production storage, and no production credentials were used. The mock replies with `[e2e-mock] 收到：…`, which is how model-driven states in the screenshots can be recognised.

Also installed `Noto Sans CJK SC` into `/usr/share/fonts` (the container shipped no CJK font, so every Chinese label rendered as tofu boxes in early screenshots `01`–`09`).

## New finding

### F9 — F4 is not fixed in the browser: two `team.list` reads per fresh mount (low/medium, blocks the "one call" claim)

Measured three times, deterministic: `team.list` at ≈1.2–1.3 s and again ≈1.7–1.8 s after navigation, with all other baseline reads at one each. The guard added in t4 (skip the first `onopen` fan-out for change subscribers) is present in the served bundle and unit-covered, but it is not what produces the second call:

- the two call sites differ (stack frame `loadColors` = `team-trigger-enhancer.tsx:210`, `load` = the always-mounted `load()` observers around `session-row-hider.tsx:53` / `sidebar.tsx:245`);
- both fire with the team section **unmounted** (原生 mode reload still 2), so neither is the sidebar roster;
- the `EventSource` open events (t≈1300 / 1367 ms) do **not** produce a third read, so the removed fan-out stayed removed.

Suggested fix direction (not implemented here): give the global observers one shared mount snapshot — e.g. the enhancer's colour read consumes the roster/observer result instead of issuing its own `team.list`, or both read through one cached promise with a short settled cache — then re-measure with `/tmp/e2e/t5-f4.mjs`.
