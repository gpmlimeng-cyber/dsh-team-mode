# DSH-Team Mode 收尾总结（2026-10-20）

> 本文记录 v0.3.0 的交付内容。当前发布版本为 **0.4.0**（2026-10-23），
> 增量与发布复检见 [CHANGELOG.md](../CHANGELOG.md) 与本文第 8 节。

## 1. 交付结论

本日交付 `@limeng/dsh-team-mode` v0.3.0 的 AionUi 风格 Team Mode：

- 左侧 DSH 会话列表内新增「团队」分组，和原生「工作区」同一套行样式。
- 团队创建 / 成员管理仍是 Modal，不替换 DSH 主界面。
- 团队成员 Session 保持原生 DSH 会话：消息流、输入框、附件、@、右侧文件/变更 sidebar 全部复用官方组件。
- 团队成员 Session 新增两个原生 conversation view：
  - **并行**：每个成员一列，独立官方 `InputBar` / input hub。
  - **看板**：任务状态分组、筛选、动态流。
- 成员栏支持添加成员、Leader 皇冠/状态点、模型 pill、每列身份色。
- 单聊 Header 支持成员切换；团队管理支持成员改名。
- 采用 A 方案：
  - **Member = Session**
  - **Task = Board**
  - **Team = 一个共享 Workspace**
  - 不引入 task 独立 Session / 独立 Workspace。

## 2. 并行视图的技术结论

之前判断“每列拿不到官方 Composer”，实际是两件事：

1. `conversation.content` 的 embedded occurrence 本来就会渲染 `[data-composer-seat]`，并绑定该 Pane 的 `SessionProvider`。
2. 真正的缺陷是**高度链**：并行墙继承了消息列的自然高度，anchor 被撑到 2781px，Pane 的 Composer seat 被推到冻结滚动视口外；视觉上就像没有 Composer。

最终修复（插件内完成，**不需要 DSH core patch**）：

- anchor 绝对定位填满可见聊天视口；
- 隐藏外层常驻 Session 的 Composer seat；
- 每列 `[data-conversation-scroll]` 撑满列高；
- Pane 内 `[data-composer-seat]` 使用 `margin-top:auto` + `sticky bottom:0`；
- 空会话保留官方 hero，不再叠加会遮挡 Composer 的自绘引导层。

## 3. 用户可见功能

### 侧栏 / 团队

- 团队分组、Leader、成员数、运行状态、待确认角标。
- 团队任务列表作为任务入口；点击任务打开 owner 成员 Session。
- 新建团队弹窗：900px 双列、成员模板、Workspace、Leader 单选。

### 并行

- 每列独立官方 Composer：模型、权限、发送、附件、draft 独立。
- 每列身份色：蓝 / 绿 / 琥珀 / DeepSeek / 红 / 蓝 / 绿 / 琥珀。
- 40px 列头：成员名、Leader、模型 pill、状态点。
- 成员栏 44px，32px 胶囊，`+` 添加成员。
- 外层不滚动；只有每列官方消息流滚动。

### 单聊 / 成员

- `conversation.session.header.actions` 成员切换器。
- 团队管理内双击/铅笔改名，调用 `team.renameMember`。
- 普通成员单聊不显示团队引导卡，避免污染正常会话。

### 看板

- 任务按状态分组，支持搜索、状态、成员筛选。
- 右侧活动流。
- 点击任务打开 owner 成员 Session。

## 6. 已知限制

- 空成员列仍使用官方 DSH hero；AionUi 中央大 Logo + 建议卡没有做成会遮挡 Composer 的覆盖层。
- `uiConversation.binding: unknown session` 在部分硬刷新/恢复顺序下仍可能出现，不影响并行主链路，但需要继续收敛。
- 线上演示团队「软件研发团队」当前 0 任务，看板空态是真实数据；要演示任务卡需先建任务。
- 诊断过程误发的 “Composer seat React con...” 成员消息和 blank Session 需要手工清空/归档。
- 单聊 switcher、添加成员弹窗、改名交互只做了代码验证，未逐项截图。

0.4.0 是发布就绪版本，不包含外部发布、部署或打标签动作。tag `v0.3.0` 保留为历史记录，没有移动或重打。

- `package.json` 版本改为 `0.4.0`；安装文档、迁移文档、CHANGELOG 与 tarball 文件名使用同一 pin。
- 文件白名单收窄为运行时与用户文档：`lib`（用 `!lib/*.map` 排除 source map）、`lib/index.js`、`locale/*.json`、`icon.svg`、`cordis.patch.yml`、README、CHANGELOG、`docs/*.md`、`docs/assets/dsh-team-mode/*.png`；`src/`、`tests/`、`scripts/`、`.github/`、`docs/assets/ui-review/`、`docs/UI-REVIEW.md` 与内部计划不打包。
- tarball 从 24.9 MiB（28.7 MiB 解包）降到 7.5 MiB（9.2 MiB 解包，41 个文件）。
- `zod` 只保留 peer + dev 依赖，不再重复安装。
- `tsdown` 的 CSS 虚拟模块 id 改为源码相对路径的哈希，`lib/client.js` 不再包含构建机的绝对路径。
- 新增 `.github/workflows/ci.yml`：Node 22/24 执行 `npm ci` + `npm run check`；Node 22 额外执行 `npm run release:smoke`（pack + 安装到临时 `DSH_HOME`）。工作流没有任何 publish/deploy 步骤。
- 新增 `npm run release:smoke`：校验必需文件与禁止文件、扫描绝对路径和凭据、安装 tarball 后确认 `lib/client.js` 存在。没有 `dsh` 命令时只跳过安装段。
- `dsh-plugin-dev check`：10 passed / 1 failed / 2 warned / 3 skipped。剩余项的逐条解释见 8.1。

### 8.1 dsh-plugin-dev check 例外

1. **`manifest-peers`（失败，接受）**
   - 检查器把 `@deepseek-ai/dsh-api-workspace-controller/client`、`@deepseek-ai/dsh-client-ui-renderer/client`、`@deepseek-ai/dsh-client-ui-workspace/client` 三个带 `/client` 子路径的 import 当成独立包名，误报“没有 peerDependency”。实际 peer 已按基础包声明，这是检查器的子路径误报。
   - 检查器要求 `>=0.1.2-rc.1 <0.3.0` 这类跨代范围，并要求 `@deepseek-ai/cordis@^4.0.2`、`@deepseek-ai/schemastery@^3.18.2`。本插件只在 DSH `0.2.1-rc.2` + cordis `4.0.5` + schemastery `3.18.5` 上验证过，因此保留窄范围，不宣称未测试的 0.1.x/0.2.0 兼容性。
2. **`manifest-package-manager`（警告，接受）**：仓库构建与 CI 使用 npm + 已提交的 `package-lock.json`（lockfile v3）；pnpm 只在用户执行 `dsh plugin add` 时使用。把仓库 pin 到 pnpm 会描述错误的安装路径。
3. **`readme-five-langs`（警告，接受）**：项目只维护英文与简体中文两份 README，其余三语没有翻译。
4. **跳过项**：`readme-consistency`（英文在 `README.md`、中文在 `README_CN.md`；检查器只识别 `README-<lang>.md` 命名，因此认为只有一份 README）、`redline-persona-role`（没有 SKILL.md）、`redline-no-hardcoded-tunables`（检查器未识别 src/config.ts 导出的 Config schema）。
