# DSH-Team Mode 收尾总结（2026-10-20）

## 1. 交付结论

本日交付 `@limeng/dsh-team-mode` v0.3.0 的 AionUi 风格 Team Mode：

- 左侧 DSH 会话列表内新增「团队」分组，和原生「工作区」同一套行样式。
- 团队创建 / 成员管理仍是 Modal，不替换 DSH 主界面。
- 团队成员 Session 保持原生 DSH 会话：消息流、输入框、附件、@、右侧文件/变更 sidebar 全部复用官方组件。
- 团队成员 Session 新增两个原生 conversation view：
  - **并行**：每个成员一列，独立官方 `InputBar` / input hub。
  - **看板**：任务状态分组、筛选、动态流。
- 成员栏支持添加成员、Leader 皇冠/状态点、模型 pill、每列身份色。
- 单聊 Header 支持成员切换；团队管理支持成员改名。
- 采用 A 方案：
  - **Member = Session**
  - **Task = Board**
  - **Team = 一个共享 Workspace**
  - 不引入 task 独立 Session / 独立 Workspace。

## 2. 并行视图的技术结论

之前判断“每列拿不到官方 Composer”，实际是两件事：

1. `conversation.content` 的 embedded occurrence 本来就会渲染 `[data-composer-seat]`，并绑定该 Pane 的 `SessionProvider`。
2. 真正的缺陷是**高度链**：并行墙继承了消息列的自然高度，anchor 被撑到 2781px，Pane 的 Composer seat 被推到冻结滚动视口外；视觉上就像没有 Composer。

最终修复（插件内完成，**不需要 DSH core patch**）：

- anchor 绝对定位填满可见聊天视口；
- 隐藏外层常驻 Session 的 Composer seat；
- 每列 `[data-conversation-scroll]` 撑满列高；
- Pane 内 `[data-composer-seat]` 使用 `margin-top:auto` + `sticky bottom:0`；
- 空会话保留官方 hero，不再叠加会遮挡 Composer 的自绘引导层。

## 3. 用户可见功能

### 侧栏 / 团队

- 团队分组、Leader、成员数、运行状态、待确认角标。
- 团队任务列表作为任务入口；点击任务打开 owner 成员 Session。
- 新建团队弹窗：900px 双列、成员模板、Workspace、Leader 单选。

### 并行

- 每列独立官方 Composer：模型、权限、发送、附件、draft 独立。
- 每列身份色：蓝 / 绿 / 琥珀 / DeepSeek / 红 / 蓝 / 绿 / 琥珀。
- 40px 列头：成员名、Leader、模型 pill、状态点。
- 成员栏 44px，32px 胶囊，`+` 添加成员。
- 外层不滚动；只有每列官方消息流滚动。

### 单聊 / 成员

- `conversation.session.header.actions` 成员切换器。
- 团队管理内双击/铅笔改名，调用 `team.renameMember`。
- 普通成员单聊不显示团队引导卡，避免污染正常会话。

### 看板

- 任务按状态分组，支持搜索、状态、成员筛选。
- 右侧活动流。
- 点击任务打开 owner 成员 Session。

## 6. 已知限制

- 空成员列仍使用官方 DSH hero；AionUi 中央大 Logo + 建议卡没有做成会遮挡 Composer 的覆盖层。
- `uiConversation.binding: unknown session` 在部分硬刷新/恢复顺序下仍可能出现，不影响并行主链路，但需要继续收敛。
- 线上演示团队「软件研发团队」当前 0 任务，看板空态是真实数据；要演示任务卡需先建任务。
- 诊断过程误发的 “Composer seat React con...” 成员消息和 blank Session 需要手工清空/归档。
- 单聊 switcher、添加成员弹窗、改名交互只做了代码验证，未逐项截图。
