# 主界面还原度评估（不改 DSH 前提）

> 2026-10-29 · 输入：OpenBot 主界面截图 + 宿主 `@deepseek-ai/dsh-client-ui-conversation` 暴露的 27 个会话槽位（已核对 bundle）。
> 结论先行：**右侧面板与左侧列表能到 90%/80%；中间消息流是 0 控制**——宿主不提供消息级槽位。

## 1. 宿主真正给我们的 27 个会话槽

```
conversation.view(=list)  conversation.session  conversation.content  conversation.composer
conversation.composer.bar  conversation.composer.dock
conversation.header  header.leading  hero.options  hero.workspace  hero.brand.mark
conversation.input.left / .right / .overlay / .dock / .activity / .attachments / .model / .permission / .plan
conversation.session.header / .actions / .utilities / .corner / .lineage
conversation.user.text (+ .node)
```

**没有** `conversation.message.*`、没有 step/turn 级槽、没有 assistant 气泡槽。这意味着：**消息流内部的一切（气泡、步骤条、问卡）都由宿主渲染，我们改不了样式也换不了结构。**

## 2. 逐区还原度

| 区域 | 截图里的元素 | 我们能不能做 | 还原度 | 手段 |
|---|---|---|---|---|
| **右侧面板** | 头像+铅笔、名称、称号、指令 | ✅ | **95%** | 已有 hero + 设定分组 |
| | 核心：模型、推理、备用模型 | ⚠️ | 模型/推理 100%，**备用模型 0%** | 宿主无"备用模型"概念，除非自建一层；建议不做 |
| | 已知：记忆、技能、文件、数据表 | ⚠️ | 记忆/技能 100%，**文件 40%、数据表 0%** | 文件可数附件；数据表宿主无双 |
| | 行为：自动化任务、用量、发布助手 | ⚠️ | 自动化/用量 100%，**发布助手 0%** | 没有分发通道，不做 |
| | 规则：权限、通知、高级 | ✅ | 权限 100%、通知 60%、高级 50% | 通知只能做本地开关，无法接系统通知 |
| **左侧列表** | 搜索、需要你、未分组、行内头像+预览+时间 | ✅ | **80%** | 我们已在自己的分区里自绘行；宿主原生行不能重排 |
| | 底部图标（工作区/帮助/设置） | ⚠️ | 50% | 原生底部项不可改，只能加 `sidebar.footer.action` |
| **顶部工具条** | 助手名、新话题、模型+档位、面板开关 | ✅ | **75%** | `header.actions/utilities` 可加；模型控件我们已做；新话题随批二 |
| **消息流** | 气泡、步骤条（1 个步骤 3 秒）、问卡（A/B/C/D/跳过） | ❌ | **20%** | 无消息级槽；问卡只能靠宿主的提问工具，样式不可控 |
| **composer** | ＋、发消息给 X、麦克风、发送 | ⚠️ | 输入/附件/模型 80%，**语音 0%** | `input.left/right/overlay/attachments` 可用；宿主无音频通道 |

**综合印象：形似度约 75–80%，但消息流内部 100% 归宿主。**

## 3. 三个"看起来能改其实不能"的地方（先说清，避免白干）

1. **步骤条 / 工具调用折叠**：宿主的 turn 渲染，没有插件的缝。
2. **助手气泡样式**：同上。想做卡片式消息，只能等宿主提供消息槽。
3. **内嵌浏览器面板**：宿主只有浏览器工具，没有可承载常驻 webview 的面板槽（与 `00-capability-matrix` §4 一致）。

## 4. 建议的投资顺序（按"每单位工作量的还原度"）

| 顺序 | 做什么 | 还原度增益 | 风险 |
|---|---|---|---|
| 1 | **右侧面板补齐**：把 8 个分组重排成「核心 / 已知 / 行为 / 规则」，补文件数、通知开关 | 视觉 +12% | 低（纯我们自己的 tab） |
| 2 | **左列表补齐**：「需要你」分区（复用 today-model）、行内预览+时间 | +8% | 低（自绘行） |
| 3 | **顶部工具条**：新话题按钮、面板开关 | +5% | 低（已有槽） |
| 4 | **问卡**：把待确认渲染成带选项的卡（宿主提问工具能承载就接，不能就放 `input.overlay` 上方） | +5%（体验价值最高） | 中 |
| 5 | 备用模型 / 数据表 / 发布助手 / 语音 | 0 | **不做**：宿主无对应能力 |

## 5. 一句话回答

**在不大改 DSH 的前提下，这套界面能还原到"八成像"**：右侧面板和左侧列表几乎可以做到 1:1，因为那两块本来就是我们自己的；**中间消息流只有两成**，因为宿主没有给消息级槽位——那部分要靠宿主演进，不是我们努力就能补上的。
