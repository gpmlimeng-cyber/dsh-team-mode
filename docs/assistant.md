# 单聊助手

[上一篇：助手库](./assistants.md) · [文档首页](./README.md) · [下一篇：创建团队](./creating-teams.md)

单聊助手是 Agent Team 提供的常驻个人助手：它有自己的主会话和后台任务，但不占用 Harness 原生侧栏的会话列表，也不像团队成员那样与他人共享协作任务。本文只介绍当前已经实现的能力。

## 入口与创建

侧栏在「群聊」下方新增「单聊」分组，位置在原生 Workspace / Session 列表之前。点击分组标题右侧的 `+`，打开「创建助手」表单。创建不再要求先准备助手模板，表单按四个分区组织，每个分区都写入真实字段：

1. **身份**：**起始角色**只列出内置角色与已启用的助手模板，选中后一次性填入该模板的真实名称、人设、头像、模型与预设（之后仍可逐项修改；实例不会绑定模板，模板里已失效的模型或预设会被跳过）；**头像**为 72px 预览，可点选平铺的 DiceBear 内置头像或从本地上传（PNG/JPEG/WebP，≤256KB）；**名称**必填；**分组**直接写入侧栏分组，写入失败只提示「助手已创建，但分组未写入」，不影响创建。
2. **人设**：`instructions` 文本区，写入助手的系统提示；留空使用 Agent Preset 默认。只影响之后创建或恢复的会话。
3. **模型与环境**：**Workspace**（创建后只读）、**模型**（按 Provider 分组，显示「模型名 — Provider · 思考档位」）、**思考模式**（当前模型提供档位时）、**Agent Preset**（创建时定死）。目录里有多个可用 Workspace 时，顶部提示本次创建位置。
4. **权限**：**权限预设**，只影响之后创建或恢复的会话；总协调（Coordinator）在侧栏行菜单设置，创建时不设。

卡片最大 900px、高 `min(760px, 94dvh)`：左侧 160px 分区导航（760px 以下变为横向滚动），右侧内容独立滚动，底部固定显示「取消」与「创建」。点击「创建」后依次创建实例、按需写入分组、确保主会话并打开；主会话打开失败时保留已创建的助手并提供「重试打开」，不会重复创建。

**创建时不提供**（不渲染成假 tab，导航底部与本文列出原因）：记忆（创建后在助手设置/记忆面板维护，创建时没有草稿）、技能/MCP（实例快照不开放这两个字段，只有「助手模板库」能配置，实例创建不继承）、例程（本插件没有按助手的定时任务，团队任务与提醒走团队流程）、访问（只保留 Workspace；浏览器、电脑、连接器、工具授权没有对应字段）、语音与通知（不可按助手配置，通知沿用 DSH 全局行为）。

助手模板仍可在助手库中维护，并用于团队；单聊创建只是不再依赖模板。

助手行采用两行紧凑布局：头像右下角的状态点表示活动任务，第一行显示名称、置顶标记和最近活动时间，第二行显示「待确认」「N 个任务运行中」「N 个任务排队中」或「空闲」。悬停（触屏上直接显示）可置顶，或通过 `...` 菜单选择「助手设置」「查看任务」「打开主会话」。被归档的助手不会再出现在列表中。

## 显示方式：简洁与进阶

「单聊」标题栏右侧的「显示方式」按钮可以在两种展示方式之间切换，仅影响本地侧栏，不会重新加载页面，也不会发起额外请求：

| 方式 | 行为 |
| --- | --- |
| **简洁**（默认） | 每个助手只占一行，保持 DS Bot 风格的列表。 |
| **进阶** | 在助手行下方显示内联的任务线程列表。 |

选择「进阶：显示任务线程」后，有任务的助手行左侧会出现一个展开箭头。点击箭头只展开/收起该助手的任务线程，不会打开主会话；点击助手行本身仍然打开主会话。线程按任务分组、最新活动优先排列，每行显示任务标题、状态和相对时间，点击任务行会先恢复隐藏的 worker 会话，再进入原生会话界面。展开状态按助手分别记忆（刷新后保留），默认收起；主会话本身不会重复出现在任务线程中。

进阶模式只是对已有 `assistant.task.list` 数据的另一种展示，不新增数据、工具或运行时行为。两种模式下 `...` 菜单里的「查看任务」都仍然可用。

## 主会话仍是原生界面

助手的主会话就是普通的 Harness Session，因此对话、工具调用、审批、历史记录和输入框全部沿用原生界面。插件不替换聊天 UI，也没有独立的助手聊天面板。

主会话和它的后台任务 Session 都会从原生侧栏隐藏，避免与「单聊」入口重复。它们仍然可以正常打开和持久化：点击助手行时会恢复绑定到该助手的主会话；重启或刷新后仍然进入同一个 Session。

## 后台任务与工具

主会话中的助手可以调用 `assistant_task_*` 工具，把适合独立完成的工作交给隐藏的 worker Session：

| 工具 | 作用 |
| --- | --- |
| `assistant_task_create` | 创建一个隐藏的后台任务，并先发送任务说明 |
| `assistant_task_send` | 向已有任务继续发送指令，worker 会沿用原上下文 |
| `assistant_task_list` | 列出该助手的任务及状态，默认按最新优先 |
| `assistant_task_wait` | 在限定时间内等待任务结束；超时返回当前状态，不会无限阻塞 |
| `assistant_task_summary` | 读取有界摘要并把它保存为任务结果 |
| `assistant_task_cancel` | 取消任务当前回合，并把任务标记为已取消 |

worker Session 不会出现在原生侧栏，也不会收到 `assistant_task_*` 工具，因此任务不会继续向下委派。每个任务拥有独立上下文，只有有界摘要会回到主会话。单个助手默认最多同时运行 4 个任务，并发上限可在插件配置中调整。

## 任务状态

| 状态 | 含义 |
| --- | --- |
| `queued` | 任务已创建，等待 worker 开始执行 |
| `running` | worker 正在执行 |
| `needs_input` | worker 停在需要用户确认的状态 |
| `completed` | 任务正常结束 |
| `failed` | 任务出错结束，错误信息保存在任务记录中 |
| `cancelled` | 任务被取消 |

「单聊」行会按活动任务（`queued` / `running` / `needs_input`）显示状态点和第二行摘要，按优先级取最高状态：

- 有任务处于 `needs_input`：警示色状态点，第二行「待确认」；
- 否则有任务处于 `running`：绿色状态点，第二行「N 个任务运行中」；
- 否则只有任务处于 `queued`：中性状态点，第二行「N 个任务排队中」；
- 没有活动任务、任务全部结束，或助手已归档：不显示状态点，第二行「空闲」。

点击 `...` 菜单中的「查看任务」可打开该助手的任务列表。任务按最近活动倒序排列，点击任一行会关闭列表并打开对应的隐藏 worker Session。列表只读取现有任务，不提供创建、取消或审批操作。

> **`needs_input` 的注意点**：当前插件依赖 Harness 上报 worker 的等待审批状态，并且没有提供任务审批界面。当宿主不上报该状态，或 worker 停在审批提示上时，任务可能继续保持 `running` / `needs_input`，需要以主会话中的工具结果为准。

## 助手设置与归档

`...` 菜单中的「助手设置」打开当前助手的设置对话框：

- 可以修改**显示名称**（必填，保存时去掉首尾空格）和**头像**。头像只接受本地 PNG、JPEG、WebP 图片，大小上限 256KB；上传后先在本机预览，保存时才写入，也可以「清除头像」。
- 可以选择**模型**（按 Provider 分组的 Provider + 模型）和**权限预设**；当前模型提供思考档位时，还可以选择**思考模式**。模型与思考档位按助手模板相同的规则校验，无法解析时返回 `MODEL_REFERENCE_INVALID`；权限预设不存在时返回 `PERMISSION_PRESET_INVALID`。切换到不支持原档位的新模型时，实例回退到该模型的默认档位。
- 只读展示助手模板（若实例由模板创建且模板仍存在；直接创建的单聊助手没有该关联）、Workspace（标题与路径）、状态和创建时间。
- **Workspace 在创建后保持只读**。模型、思考模式和权限预设只写入实例快照，不会修改助手模板；模板配置仍由助手库维护。
- 已打开的主会话会沿用旧模型与权限，直到它被重新创建或恢复；保存后新建的后台任务、以及未来恢复的主会话，使用保存后的新快照。刷新侧栏不会重建主会话。
- 保存成功后对话框关闭并刷新侧栏列表；保存失败时错误显示在对话框内，已编辑内容会保留。
- 归档需要两步：先点击「归档助手」，再点击「确认归档」。归档会立即停用该助手：从「单聊」列表移除、停掉已打开的主会话与会话线程、取消正在运行的后台任务（包括在已完成任务上恢复出来的 worker）；助手记录、主会话日志、工作区文件和已有任务记录都不会被删除，也不会自动清理。若该助手仍被某个**未归档团队**的成员关联，归档默认被拒绝（`ASSISTANT_INSTANCE_TEAM_LINKED`，错误信息点名团队并给出两条路）；带 `force` 归档后，团队侧这条关联会被标记为已失效（`assistantInstanceArchivedAt`），团队页成员行显示「已归档」、团队记忆不再注入，恢复助手后关联自动恢复。恢复有入口：侧栏「已归档」分组逐行恢复，或在本设置面板的「归档」区恢复。恢复只恢复可用性——归档时被取消的后台任务保持 `cancelled`，不会被重新排队或重放；恢复后再次打开助手会以原主会话日志 resume 出一个新的 Agent（不是复活归档前那个），归档期间该助手打不开：主会话绑定与新建会话都会被拒绝（`ASSISTANT_INSTANCE_ARCHIVED`）。

## 持久记忆

每个单聊助手有一份持久记忆，由它的所有会话共享，分为两层：

- 旧版短文本 `content`：`assistant_memory_read` 读取，`assistant_memory_write` 替换或追加；写入超过 16,000 字符会被拒绝，而不是截断。
- 结构化条目 `entries`：`assistant_memory_entry_write` 新建或修改单条记忆，`assistant_memory_read` 一并返回条目。条目带有 `visibility`（默认 `private`）、`status`（`active` / `archived`）、`source`、可选 `key`、`title`、`body`，以及条目自身的 `revision`。
- 只读召回：`assistant_memory_read` 可用可选的 `query`（对 `key` / `title` / `body` 做不区分大小写的包含匹配）、`status`（只返回该状态）和 `limit`（1–50，默认 20）缩小返回条目；结果附带 `total` 与 `truncated`，单次返回的正文共享 8,000 字符预算。召回只读，不会修改记忆，也不会跨出本助手的容器。
- 变更日志 `journal`：结构化条目每次新建、修改、归档都会在同一个原子写入中追加一条日志，记录 `action`、`actor`、`reason`、变更前后的内容快照，以及该次写入产生的记忆版本。日志只保留最近 10 条，助手侧总计不超过 16,000 字符（团队侧 8,000 字符），超出时丢弃最旧记录。旧版文本写入不写日志。快照会脱敏常见凭据（私钥、`sk-` / `ghp_` / `xoxb-` 等令牌、`password=` / `token:` 赋值）；被脱敏或截断的记录标记为不可撤销。
- 撤销：界面通过 `assistant.memory.undo`（不是模型工具）撤销一条日志。日志 id 必须位于当前助手的记忆容器内，且该条日志必须正是产生当前记忆版本的那次变更，否则返回 `MEMORY_UNDO_STALE`；撤销把记录中的 before 快照精确恢复为新版本（若原是新建则归档该条目），脱敏/截断记录返回 `MEMORY_UNDO_UNAVAILABLE`。撤销本身也会追加一条 `undo` 日志。
- 自动捕获（默认关闭）：部署配置 `memoryAutoCapture=true` 时，后台 worker 任务完成会写入 1 条 `private`、`proposed`、`source=auto` 的条目（`key=task:<taskId>`，标题来自任务标题、正文来自 `resultSummary`）。内容先脱敏再截断（标题 200、正文 4,000 字符），按 key 与规范化文本去重，复用记忆写入锁；同一任务不会重复捕获，任务未完成或捕获失败时不写入，完成状态不受影响。捕获不会自动接受任何条目，也不会调用模型。
- 主会话和 worker 都会在系统提示中获得旧版文本；结构化条目只注入主会话，且只注入 `active` 条目（最多 20 条、每条正文截断到 200 字符）。worker 只读，不能修改记忆。
- 旧版文本存储上限是 16,000 字符，但每次只把前 4,000 字符注入提示；结构化条目的 title+body 合计同样限制在 16,000 字符、最多 100 条，超出会拒绝写入。上限只统计未归档条目：把旧条目标记为 `archived` 即释放额度，归档内容仍保留在存储里但不再计入上限，也不再进入提示。

写入使用文档级版本栅栏：`assistant_memory_entry_write` 的 `expected_revision` 必须是 `assistant_memory_read` 返回的当前记忆版本（尚无记忆时为 `0`），过期版本返回 `MEMORY_REVISION_CONFLICT`，不会覆盖他人刚写入的内容。同一助手的记忆写入按顺序串行执行，因此并发首次写入（`expected_revision=0`）也只有一个成功，另一个得到冲突错误，不会丢失条目。修改已有条目时该条目自身的 `revision` 加一；`entry_id` 必须是已存在的条目，未知 id 会被拒绝而不是当作新建。

`visibility: team-safe` 只在团队成员显式关联到该助手实例时才会进入团队会话：插件只注入 `active`、`scope=assistant`、`team-safe` 的结构化条目（长度有界），`private` 条目、提案、归档条目以及旧版 `content` 都不会进入团队提示词。成员在团队里只能读取，没有 `assistant_memory_*` 写入工具。关联必须由创建/更新成员的调用方显式提供，插件不会根据助手模板或 Workspace 推断；未关联的成员（包括旧成员）行为不变。实例归档或不可用时注入降级为空，不会中断成员会话。详见[团队管理](./team-management.md)的「关联单聊助手实例」。

助手设置对话框底部提供「持久记忆」面板，用于查看和修改这份记忆：

- 旧版文本单独显示，可直接编辑或两步确认清空；结构化条目按状态分组，显示可见性（私有 / 团队可见）、状态、来源、条目标题、正文和条目 `revision`。
- 可以新建条目、编辑已有条目、归档条目；历史（`archived` / `superseded`）内联显示，只渲染最近 20 条。
- 变更日志单独列出每条记录的动作、操作者、时间与原因；对未脱敏/未截断的记录可点「撤销」，撤销会按记录恢复精确的前一版内容，新建记录则归档该条目。
- 面板读取 `assistant.memory.get`，写入使用当前记忆版本作为 `expected_revision`。版本过期时服务返回 `MEMORY_REVISION_CONFLICT`（旧版文本为 `ASSISTANT_REVISION_CONFLICT`），面板提示冲突并重新加载最新版本，不会覆盖他人刚写入的内容。撤销使用 `assistant.memory.undo`，过期返回 `MEMORY_UNDO_STALE` 并重新加载。
- 已归档助手仍可打开面板查看记忆，但服务层会拒绝写入。

## 当前限制

- **任务恢复**：宿主重启或插件重载会丢失 worker 句柄。任务会在下次需要 worker 的操作（例如继续发送消息）时惰性恢复；如果恢复失败，该操作返回错误，不会假装任务仍在运行。恢复能力受 Session 与 Workspace 状态影响。
- **主会话所有权**：主会话的 Agent 如果已经被其他生命周期持有（例如插件重载时上一个实例尚未释放，或原生会话控制器恢复了同一个 Session），插件无法把 `assistant_task_*` 工具和持久记忆补挂到已存在的 Agent 上，也不会销毁不属于自己的 Agent。此时打开主会话会返回 `AGENT_HANDLE_OWNERSHIP_CONFLICT`，不会进入一个缺少助手工具的会话；等该持有者释放后再次点击助手行即可正常恢复，不会重复创建助手。重试只在持有主会话的插件生命周期（例如插件重载）释放该 Session 后有效；如果主会话由 DSH 原生会话控制器持有，则只有重启 DSH Host 才能清除该所有权。
- **worker 会话所有权**：worker 的 Session 如果仍然被其他生命周期持有（例如插件重载时上一个实例尚未释放），插件不再被动接管该 Agent，而是返回 `AGENT_HANDLE_OWNERSHIP_CONFLICT`（附带 `taskId`、`sessionId`），并且不会取消或销毁不属于自己的 Agent。等原持有者释放该 Session 后重试即可正常恢复；如果由 DSH 原生会话控制器持有，则只有重启 DSH Host 才能清除该所有权。
- **审批**：worker 继承助手的默认权限；插件不提供自动审批，也没有任务级审批界面。`needs_input` 只是如实记录阻塞状态，不保证有入口解除阻塞。
- **任务界面**：侧栏行和第二行摘要可以观察任务状态；「进阶」模式可在助手行下展开任务线程，「查看任务」可打开完整任务列表，两者都会进入隐藏 worker Session。仍没有任务详情、任务级审批、创建或取消入口，创建仍由主会话中的 `assistant_task_create` 完成。
- **记忆编辑**：设置对话框中的记忆面板支持手动查看/编辑，并可撤销最近 10 条变更日志；自动捕获仅在 `memoryAutoCapture=true` 时把完成结果写成 `proposed`，不会自动接受；召回只有 `query` 子串匹配，没有语义召回或向量检索界面。记忆仍主要由助手通过工具维护。
- **团队关联入口（已知缺口）**：团队成员与单聊助手实例的关联已支持 API/服务层——创建团队、`team.addMember`、`team_spawn_agent` 可传实例 ID，更新/解除用 `team.member.setAssistantInstance`（`null` 解除）。本期**没有界面选择器**，也不能从助手侧反向管理关联；团队关联的状态只在团队侧以「已归档」标记可见。相关校验（工作区一致、跨团队唯一、独立工作区不可入团队）都在服务层，UI 只负责展示原因。
- **多 Host**：未实现多 Host 共享、只读协作或写入所有权协商；请勿让多个 Host 同时操作同一份插件数据。
- **设置范围**：设置对话框支持显示名称、头像、模型、思考模式与权限预设；Agent Preset 与人设在创建时写入，设置对话框暂不修改这两项。Workspace 在实例创建后只读，助手模板本身仍由助手库维护。
- **归档**：归档助手会将其从「单聊」列表移除、停掉主会话与会话线程，并取消正在运行的后台任务（包括在已完成任务上恢复出来的 worker）；已存在的任务记录、主会话日志和工作区文件不会因此自动清理。仍被未归档团队关联时归档默认被拒绝，需先从团队移除（或归档该团队），或用 `force` 强制归档——强制的关联会以「已归档」标记留在团队侧。恢复入口在侧栏「已归档」分组与设置面板；恢复只恢复可用性，归档取消的任务不会复活。

## 与团队模式的关系

单聊助手与「群聊」里的团队成员是不同实例：单聊助手不占用团队席位，也不参与团队任务和团队消息。单聊助手可以直接创建，不需要先准备助手模板；旧版或通过模板创建的实例仍保留模板关联。助手模板仍可加入团队，但它不再是新建单聊助手的前置条件。

**独立工作区 × 入团队**：创建对话框的「独立工作区」默认开启（`workspaceIsolated: true`），助手会拿到 `<基础目录>/.dsh-team-mode/assistants/<slug>-<id8>` 这个私有目录，因此它**不能**关联到团队——关联会返回 `ASSISTANT_INSTANCE_WORKSPACE_MISMATCH` 并提示「创建时关掉独立工作区」。要在团队里使用的助手，创建时必须关掉该开关，与团队共用同一个 Workspace。两个独立工作区助手不会共享目录，归档/恢复也不会删除它们的目录（`tests/assistant-lifecycle-e2e.spec.ts` 断言了这条路径）。团队关联入口本身仍只有 API，见[团队管理](./team-management.md)的已知缺口。
