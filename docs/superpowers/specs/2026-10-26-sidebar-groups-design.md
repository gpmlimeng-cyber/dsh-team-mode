# 侧栏自定义分组（团队模式）— 设计

> 2026-10-26 · 目标插件 `@limeng/dsh-team-mode` · 状态：待评审
> 参考：MausBot 的自定义侧栏分区（本机无源码克隆，按通行交互设计，不声称逐字对齐）

## 目标

团队模式的侧栏里，用户能把**团队**和**单聊助手**各自归入自定义分组，分组在列表中以可折叠分区渲染。默认全部「未分组」，行为与现状一致。

## 数据

分组是**实体**（对照 MausBot `AppState.sections: string[]`），不是一个派生出来的名字集合：

| 记录 | 字段 | 约束 |
|---|---|---|
| 分组列表 | 有序 `string[]` | 去重、去空白、每项 ≤ 40；顺序即渲染顺序；**允许为空组** |
| 团队聚合 | `group?: string` | 必须是已存在的分组名；空串归一为 undefined |
| 助手实例 | `group?: string` | 同上 |

有了列表才有重命名、删除（级联置空成员）和稳定顺序；代价是不能靠"成员没了分组自动消失"，所以删除必须级联，写入必须校验存在性——**不允许写入不存在的分组名**（否则出现指向幽灵分组的条目）。

## 传输

- 条目归属：`team.group.set { teamId, group: string | null }` → `TeamView`；助手复用 `assistant.instance.update`（`group: z.string().optional()`）。
- 分组列表：`sidebar.groups.list` → `string[]`；`sidebar.groups.create { name }`、`sidebar.groups.rename { from, to }`、`sidebar.groups.delete { name }`、`sidebar.groups.reorder { names }`，均回 `string[]`。
- 改名与删除**级联**：改名把所有 `group === from` 的团队/实例改为 `to`；删除把它们置为未分组。

## 交互

- 团队行「⋯」菜单新增一项「移动到分组…」（排在置顶与"管理"之间）。
- 单聊助手行「⋯」菜单同样新增一项。
- 点击后弹一个轻量对话框：列出已有分组（单选）+ 一个输入框（新建分组名）+ 「不分组」选项。
- 选定后立刻写后端并刷新；失败显示错误，不改本地态。

## 呈现

- 群聊区：`<未分组>` + 各分组，组头复用现有团队 section 的折叠头样式。
- 单聊区：同样分区。
- 空分组不渲染；只有「未分组」有内容时，不显示分区头（保持现状观感）。

## 与 MausBot「部门」的差异（已确认的范围边界）

MausBot 的分组是**部门实体**：有组级共享指令/记忆、可批量套设置（`Set for all bots in this department`）、可导出分享（`Share department…`）。我们这一轮只做**视图级分组**——归组、改名、删除、排序、拖拽。

明确不做，且不是因为难：
- **组级共享指令/记忆**：团队本身已经有 Leader、任务、收件箱和记忆，再加一层组记忆会变成三层组织。
- **组内批量设置**：要动团队的模型/权限字段，属于另一个功能。
- **导出/分享分组**：产品方向问题，不是侧栏问题。

要其中任何一项，单独开设计，不混进这轮。

## 明确不做

- 不做拖拽（Electron 内拖拽与滚动/折叠交互冲突，成本高）。
- 不做嵌套分组、分组颜色、分组排序（按名称排序即可）。
- 不做跨设备同步之外的额外能力——后端存字段本身已跨设备一致。

## 验收

1. 把团队 A 设为「工作」、助手 B 设为「工作」→ 两个分区各自出现「工作」，重名分组在两侧独立成立。
2. 清除分组 → 条目回到「未分组」，空的「工作」分区消失。
3. 分组名去空白、超 40 字被拒绝（返回错误码，不静默截断）。
4. 全部未分组时，侧栏与改动前逐像素一致（无多余分区头）。
