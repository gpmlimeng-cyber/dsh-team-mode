# 今天（Today 首页）

> 2026-10-28 · 借鉴 baize-bot 的首页：**一个页面回答「我现在要不要动手」**，而不是一个通知中心。

## 1. 它解决的问题

打开 DSH 现在看到的是"最后一次会话"。要知道"有没有事等我"必须逐个团队点开——这正是产品分析里 P1 的缺口。

**首页只做三件事**：告诉你有没有事等你、正在跑什么、接下来会自动发生什么。

## 2. 抬头那句话（最重要的一行）

```
陈，下午好
2 件事等你，其余在按计划跑
```

规则：

| 情况 | 文案 |
|---|---|
| 有待确认/卡住 | `{n} 件事等你，其余在按计划跑` |
| 无待确认，有在跑 | `都在按计划跑` |
| 什么都没有 | `今天没有等你的事` |

**这一行是整页的价值所在**：用户看完它就可以关掉页面。

## 3. 三块内容（顺序即优先级）

### 3.1 等你确认（第一位，可折叠逐条）

来源：

- 团队的待确认（escalation）——`team.list` 已有；
- **卡住的成员**（任务失败/需要介入）——成员状态已有。

每行：`团队名 · 事项` + 等待时长 + 直达按钮。**超过 10 条才折叠**，前面全展开。

空态：整块不渲染（不显示"没有待确认"这种废话）。

### 3.2 在进行

来源：有 `running` 任务或 `working` 成员的团队。

每行：团队名 + 一句当前在做什么 + 已跑时长。点行 → 进该团队。

空态：一行灰字 `现在没有在跑的任务`。

### 3.3 接下来

来源：自动化（schedule catalog）下一次触发时间 + 团队例行（若以后有）。

每行：`{名称}` + `{下次时间}`（相对 + 绝对，如 `明天 09:00`）。点行 → 打开该自动化。

空态：整块不渲染。

## 4. 入口与形态

- **入口**：侧栏品牌行 `＋` 菜单里加一项「今天」，或在侧栏顶部一个不带边框的「今天」行（与 baize 一致）；
- **形态**：右侧栏的一个 tab（复用现有 `sidebarRightTabs.register`，与助手设置/团队页同一套），**不做整页路由**；
- 关闭后状态保留（不记住滚动位置，YAGNI）。

## 5. 数据与成本

| 项 | 来源 | 新增请求 |
|---|---|---|
| 待确认 | `team.list` 的 escalation 字段 | 无 |
| 卡住成员 | 同上（成员状态） | 无 |
| 在进行 | 同上（任务状态） | 无 |
| 接下来 | `schedule` 只读投影（我们已在用量面板读过） | 无 |

**不调模型、不存新数据、不做后台轮询**：页面打开时拉一次，页面内手动刷新按钮。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 今日简报（定时消息） | 已 park：一天一次的消息对"一天开十次"的用户太迟钝，首页是常驻的 |
| 通知中心 / 未读消息列表 | 那是"更多内容"，首页要的是"更少判断" |
| 自定义板块、拖拽排序 | 先看默认三段有没有人用 |
| 模型生成的"人话总结" | 抬头一句话由数据合成即可，模型只会让它变慢变贵 |

## 7. 验收

1. 抬头文案三态正确（有等待 / 全在跑 / 空）；
2. 三块的空态规则：等你确认与接下来为空时不渲染，在进行为空时一行灰字；
3. 每一行都能点到对应目标（团队页 / 自动化面板），不是死链；
4. 打开页面只发**一次**数据请求，不轮询；
5. 没有待确认时，抬头不会出现"0 件事等你"；
6. `npm run check` 全绿。
