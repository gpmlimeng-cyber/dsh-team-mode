# 今日简报（团队例行）

> 2026-10-28 · 借鉴 baize-bot 的「例行」：到点替你做一件事，结果你自己会来看。
> 这里的定位：**每天一条，告诉你这个团队今天发生了什么、现在需要你做什么。**

## 1. 为什么做这个

用户不打开团队，就不知道团队在干什么；打开了还要翻任务、翻会话、翻待确认。简报把「今天」压缩成一条消息，**放在你一定会看到的地方**（团队主会话）。

## 2. 关键决定：不做定时器，做「懒补发」

baize 用调度器 + webhook 触发。我们**不引入调度基础设施**，理由是：

- 插件只在 DSH 运行时才有意义，用户没开 DSH 时发简报没人看；
- 定时器要处理休眠、跨天、时钟跳变，成本远大于收益。

改成：

```
打开 BOT 模式时检查：
  今天（本地 04:00 为日界）还没发过
  且现在已过设定时间（默认 21:00）
  → 合成并发送一条；发完记 lastSentDay
错过整天不补（周一不补上周五）
```

**代价**：如果你整天不开 DSH，那天的简报不会有——但它本来也没机会被看到。**收益**：零调度代码、零时区坑、零后台进程。

## 3. 内容（全部来自已有数据，不调模型）

```
今日简报 · 10月28日

完成 3 · 进行中 2 · 待你确认 1

需要你做的事
  1. 「发布检查」等待确认（等了 2 小时）

成员
  调研    在跑「竞品对齐」        12 分钟前
  开发    空闲                     2 小时前
  测试    卡住：工具报错           40 分钟前

会话
  新增 2 条，其中 1 条你没看过

今日用量
  12.4k tokens · 8 轮
```

规则：

- **空就省略整段**（没有待确认就不出现"需要你做的事"）；全空时只发一句「今天没有新进展」；
- **不调模型**——纯本地合成，每天的简报成本是 0；需要"人话总结"是另一件事（见 §6）；
- 数字来自 `team.tasks`、`escalations`、成员状态、`team.threads`、用量投影。

## 4. 状态与自动暂停（借 baize）

- 状态：`on` / `paused`；默认 `on`；
- **连续 3 条简报无人查看** → 自动转 `paused`，并在设置里显示"已自动暂停（连续 3 天没人看）"，与手动暂停区分显示；
- 用户再次打开简报或手动开启 → 恢复 `on` 并清零计数。

这条的目的不是省资源（我们几乎不耗资源），是**防止一条被无视的例行变成噪声**。

## 5. 数据与接口

```ts
// domain
teamBriefingSchema = {
  enabled: boolean,
  time: string,        // 'HH:mm'，本地时区，默认 '21:00'
  pausedReason?: 'manual' | 'unread',
  lastSentDay?: string,  // 'YYYY-MM-DD'
  unreadStreak: number,  // 连续未读次数
}

// service（新增两个方法）
team.briefing.send(teamId)      // 合成 + 发到主会话，返回消息 id（测试与手动"立即生成"用）
team.briefing.configure(teamId, { enabled?, time? })
```

发送方式：走既有 `team.message.send`（Leader 身份），**不新造消息类型**；消息带 `data-dsh-team-briefing` 标记便于已读判定。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 模型润色的叙述版总结 | 每天一次模型调用，换来的是"读起来更顺"，不值；想要就做成按钮「让领队讲讲」 |
| 自定义简报章节 | 先看默认三段有没有人用 |
| 定时器 / webhook 触发 | 见 §2 |
| 推送通知 | 宿主没有可靠的跨平台通知通道，简报本身就是"回来时的收件箱" |

## 7. 验收

1. 已过设定时间且当天未发 → 打开 BOT 模式后主会话出现一条简报；
2. 当天已发 → 不重复发；次日 04:00 后重新可用；
3. 空团队/全空数据 → 只发一句「今天没有新进展」，不出现空段落；
4. 连续 3 条未读 → 自动暂停并在设置里说明原因；
5. 不产生任何模型调用（测试断言：合成路径不触碰 model 接口）；
6. `npm run check` 全绿。
