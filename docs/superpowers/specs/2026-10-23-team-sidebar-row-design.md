# 侧栏团队行增强 — 设计方案

> 2026-10-23 · 小需求 · 优先排在 Turn Engine 之后
> 对标：AgentTeams / OpenMausBot / Grok Bot / 我们的单聊列表
> 约束：不改后端 schema，不做第二个团队页，不引入消息 N+1 请求

## 1. 问题

当前侧栏团队行只有：

```text
👥 团队名        2分钟   ●
```

用户无法一眼判断：

- 这个团队有多少人
- 有几个在运行
- 是否有待审批
- 最近在做什么

单聊行已有状态文案、未读、注意力摘要和简洁/进阶显示，团队行没有复用同一套语法。

## 2. 目标

团队行从“导航行”升级为“状态摘要 + 最近任务入口”：

```text
👥 软件研发团队                    2分钟
   3 人 · 2 运行 · 1 待审批          [1]
   ▸ 最近任务
      修复登录 bug            运行中
      写发布说明              已完成
```

侧栏只负责“找到团队 + 判断是否需要我”，不承担团队详情。

## 3. 对标结论

| 参考           | 借鉴                     | 不照抄                |
| -------------- | ------------------------ | --------------------- |
| AgentTeams     | 当前/历史分开            | 顶部大 Tab            |
| OpenMausBot    | 一个入口展开任务线程     | 全部成员/线程塞进侧栏 |
| Grok Bot       | 置顶、未读、移动端紧凑   | 消费级分组体系        |
| 我们的单聊列表 | 状态文案、未读、显示方式 | 两套不同视觉语法      |

## 4. 行的结构

### 第一行

- 团队图标/首字母/团队色
- 团队名，单行省略，title 显示全名
- 右侧相对时间
- 置顶标记
- 更多菜单

### 第二行

```text
N 人 · M 运行 · K 待审批
```

- 没有运行时只显示 `N 人 · 空闲`
- 有待审批时显示数字徽标
- 数字来自现有 `TeamView.members` 的 `lastRuntimeState`
- 另加 `等待前置`：依赖未完成的 blocked 任务数
- `待审批` 是用户注意力，用徽标；`等待前置` 是内部依赖，只做文字
- 不新增 API

### 展开区

- 默认收起
- 展开显示最近 3 个任务，按 `updatedAt` 倒序
- 每行：任务标题 + 状态
- 阻塞任务显示等待的前置任务和负责成员
- 数据来自 `TeamView.tasks`，无需额外请求
- 没有任务时显示“暂无任务”
- 点击任务打开团队页，不在侧栏直接操作

## 5. 排序与筛选

排序：

```text
置顶
→ 待审批
→ 运行中
→ 最近更新
```

- 有 `waiting_approval` 的团队优先
- 运行中次之
- 与单聊列表保持一致的注意力优先

筛选：

```text
团队 (3)   历史 (2)
```

- 默认只看进行中团队
- 历史团队单独入口，不混在列表里
- 搜索覆盖团队名 + 成员名

## 6. 操作收敛

当前 hover 同时出现管理、归档、置顶三个图标，太吵。

改为：

- 点击行：打开团队
- hover 只显示：置顶 + 更多
- 更多菜单：管理团队、归档团队
- 归档只在非 active/starting 团队可用

## 7. 与单聊列表统一

- 同一套 `sidebarTeamSection` 容器
- 同一套状态点、徽标、副标题、hover 行为
- 单聊已有“简洁/进阶”，团队行增加“展开最近任务”即可
- 不新建第二个侧栏组件体系

## 8. 响应式与可访问性

- 320px：团队名省略，第二行只保留 `N 人 · M 运行`，待审批用徽标
- 展开/收起用独立按钮，`aria-expanded` 正确
- 行本身是按钮，展开按钮不能嵌套在行按钮内
- 徽标有文本替代，不只靠颜色
- 键盘：Tab 到行 → Enter 打开；Tab 到展开按钮 → Enter 展开

## 9. 分期

**P0（优先）**

- 副标题：人数 / 运行 / 待审批
- 注意力优先排序
- hover 收敛为置顶 + 更多
- 进行中/历史显式入口

**P1**

- 展开最近 3 个任务
- 团队首字母/身份色

**P2**

- 搜索、移动端细节、归档计数
- 最后活动摘要（需要额外消息数据，先不做）

## 10. 验收

- 一眼看出哪个团队需要我
- 有等待审批时显示徽标和数量
- 运行中/空闲/异常状态与团队页一致
- 展开只显示任务，不显示成员列表
- 不新增消息请求，不产生 N+1
- 320px 不溢出，键盘可操作
- `npm run check` 通过
