# 助手设置 · 概览（Overview）设计

> 2026-10-27 · 目标：MausBot 的 Overview 语义（"这只 bot 是什么、还缺什么、能干什么"），数据只用我们已有的字段，不新增传输。
> 位置：助手设置面板的第一个分组，**默认展开**，其余分组默认收起。

## 1. 为什么要有这一页

MausBot 的 Overview（`bot-settings/OverviewSection.tsx`）不是设置项，是**体检报告 + 引导**：

1. 未完成的配置清单（可点跳转）
2. 它是什么（名字 / 一句话 / soul 摘要）
3. 能力边界（does / can reach / won't，由配置生成句子）
4. 系统提示预览

我们现在这一格是**只读元数据表**（模板 / Workspace / 总协调 / 状态 / 创建时间），而这些在**右侧详情面板**里已经有一份——设置页首屏放重复信息是浪费。

## 2. 我们的三段结构（v1）

### 2.1 待办清单（`assistantOverviewTodos`）

按"能不能一键跳过去修"排，全部由现有数据判断，**不发明字段**：

| 条件 | 文案 | 点击跳到 |
|---|---|---|
| `instructions.trim() === ''` | 写一段描述，让它知道自己是干什么的 | 设定与形象 |
| `skillAllowlist.length === 0` | 还没有授予任何技能 | 技能与MCP |
| `mcpServers.length === 0` | 还没有可用的 MCP 工具 | 技能与MCP |
| 自动化任务数 === 0 | 没有自动化任务，它不会自己定时干活 | 自动化 |
| 记忆条数 === 0 | 还没有记忆，它不会记住上次的结论 | 记忆 |

- 全部完成时**整块不渲染**（不显示"全部完成 🎉"那种自夸）；
- 每行右侧 `→`，鼠标整行可点；
- 数量最多 5 条，**不折叠**。

### 2.2 它是什么（`assistantOverviewWho`）

```
[吉祥物/头像 24px]  名称
                   描述首行（没有就显示「还没有描述」并可点去补）
                   模板 · Workspace · 权限预设        ← 一行 meta
```

- 描述**截断到两行**，非空时**始终**给「读全部」文本按钮跳「身份与形象」（不做溢出检测：测量 `scrollHeight` 在窄栏里不稳定，而多一个可见入口的代价远小于"文字被截但没有入口"）；
- `title` 属性的悬停提示**不能**替代「读全部」：键盘和触屏都到不了它；
- meta 行只保留三个最关键的：**模板 / Workspace / 权限预设**（原"创建时间 / 总协调 / 状态"留在详情面板，不重复）。

> 范围澄清：这条**只约束概览分组**。设置页顶部的 hero 副标题（分组 · 总协调 · 状态）是**身份抬头**，与 DS Bot hero 的 `role · Main Bot` 同构，保留；详情面板的元数据表同理不动。

### 2.3 能力边界（`assistantOverviewLimits`）

用**生成的句子**而不是字段表（MausBot 的做法），句子直接来自真实字段：

```
能做到
· 可以使用 3 个技能（research、plan、review）
· 可以调用 2 个 MCP 工具
· 运行在「DSH-Team Mode」工作区，权限：完全权限

不会做
· 没有自动化任务，不会自己按时执行
· 没有记忆，不会保留上次的结论
```

- "能做到"列表至少一条，否则整块显示 `还没有授予任何能力`；
- "不会做"列表**只在确实没有时出现**（有自动化就不出现那一行），也就是**永远是真实的否定**，不是模板文案；
- 数量与名单来自实例快照 / 自动化 catalog，**不额外请求**（复用已有的 `useCapabilityCatalog` 与 `assistantAutomationRows`）。

## 3. 明确不做（v1）

| 不做 | 原因 |
|---|---|
| **系统提示预览** | 宿主最终拼出的 prompt 含大量我们看不到的块（工具说明、环境），只预览我们自己那段会让人误以为那就是全部。要做必须先能拿到完整 prompt |
| 完成度百分比 / 进度环 | 5 项勾选的"完成度"是伪精确，用户不关心 60% 这种数 |
| "和 bot 一起设置"的对话按钮 | MausBot 有这个是因为它的 bot 能自己改配置；我们的助手改不了自己的实例，点进去只能是空动作 |
| 编辑能力 | 概览**只读**，任何写操作都在对应分组里做（避免两处都能改、状态不同步） |

## 4. 交互与实现约束

1. **默认展开**：`open` 初值为 `overview`，其余 `false`；搜索命中时按既有规则自动展开（已在 `FoldGroup` 里实现）。
2. **纯函数**：`assistantOverviewTodos()` / `assistantOverviewLimits()` / `assistantOverviewWho()` 三个纯函数，输入 `AssistantInstanceView` + 可选 counts，输出数据；组件只做映射，便于测试。
3. **数据来源**（全部已存在）：
   - 实例快照：`instructions / skillAllowlist / mcpServers`
   - catalog：`agentPresets / permissionPresets / workspaces`
   - 自动化：`assistantAutomationRows(...)`（详情面板已用）
   - 记忆：设置面板已有记忆条数读取路径
4. **跳转**：面板内部把 `open` 状态切到目标分组并滚动到位，不打开新界面。
5. **样式**：只用 `--dsw-*`；行高沿用 48px 的 `SettingsRow`；不新增卡片底色（分组本身就是容器）。

## 5. 验收

1. 打开助手设置 → 概览默认展开，其余收起；
2. 五项待办在缺项时出现、点一下跳到对应分组并展开；
3. 全部具备时待办块消失，页面不出现空块；
4. "不会做"只写真实缺失项（有自动化时不再说"没有自动化"）；
5. `npm run check` 全绿，三个纯函数各有断言。
