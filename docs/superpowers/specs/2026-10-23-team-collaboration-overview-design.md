# 团队协作总览 — 设计方案

> 2026-10-23 · 产品/UI 方案 · 增强现有团队看板
> 参考：AgentTeams 团队协作看板截图
> 约束：不新增独立页面，不复制团队切换/历史，不引入图形库

## 1. 结论

在现有 `TeamBoardView`（会话内“看板”标签页）里增加一个**总览 / 任务**视图切换。

- **任务**：保留现在的按成员分列任务板
- **总览**：团队运行视图，补齐进度、成员任务、依赖图、任务详情、Leader 收件箱

不新增 `/team-collaboration` 页面，不新增第二个会话 Tab。

## 2. 为什么不是新页面

- 同一个团队、同一份 `TeamView` / tasks / messages 数据
- 新页面会重复订阅、加载、同步和空态处理
- 现有看板已经是会话内的一个 view，再拆页面会让“看任务”和“看协作”分家
- 截图里的团队切换、历史团队，我们的侧栏已经覆盖，不需要复制

未来如果出现“跨团队总览”，再单独拆页面。

## 3. 入口与默认视图

看板顶部（现有 `boardHeader` 下方、工具栏上方）增加分段控件：

```text
[总览] [任务]
```

规则：

- 记住用户上次选择，storage key：`dsh-team-mode:team-board:view`
- 没有历史选择时：
  - 有 `running` / `blocked` / `failed` 任务 → 默认总览
  - 否则默认任务
- 切换不改变筛选条件；搜索、成员筛选两边共用
- 任务视图保持现有布局不动

## 4. 总览布局

```text
┌─ 团队 Header：身份 / 状态 / 任务统计 / 同步 ─────────────┐
│ [总览] [任务]   搜索 / 成员筛选 / 刷新                   │
├───────────────────────────┬─────────────────────────────┤
│ Leader 摘要                │ 任务依赖图                   │
│ 总进度条                   │ 节点可点选                   │
│ 成员与任务 chips           │                             │
│                           │ 选中任务详情                 │
├───────────────────────────┴─────────────────────────────┤
│ Leader 收件箱：最近待处理消息 / 查看全部                  │
└─────────────────────────────────────────────────────────┘
```

宽屏：左栏固定约 320–360px，右栏自适应；下方收件箱通栏。  
窄屏：全部上下堆叠；依赖图退化为按层列表，任务详情在选中节点下方展开。

### 4.1 Leader 摘要

- Leader 头像、名称、当前状态
- 一句摘要：`已派发 8 项任务给 3 名成员`
- 总进度：已完成 / 进行中 / 等待 / 异常，使用现有 task statuses
- 进度条按数量分段，附文字计数，不只靠颜色

### 4.2 成员与任务 chips

- 每个成员一行：头像、名称、角色、模型 badge
- 任务 chips：显示任务标题截断 + 状态色
- 点击 chip → 选中任务详情
- 点击成员名 → 打开成员会话（复用现有 `openTaskSession` / 会话导航）
- 空成员显示“暂无任务”

### 4.3 依赖图

- 数据只用现有 `task.dependencyIds`
- 客户端计算分层：无依赖任务为第 0 层，依赖满足后递增
- 同一层从左到右排列；节点是按钮，可键盘操作
- 节点显示：任务标题、status、owner
- 边用 CSS 连接线/箭头，不引第三方图库
- 循环依赖或缺失依赖：单独放到“未分层”区域并显示警告，不伪造顺序
- 没有依赖时显示“任务暂无依赖”，仍保留任务详情入口

### 4.4 选中任务详情

- 默认选中：第一个进行中任务；没有则第一个任务
- 内容：标题、状态、owner、依赖、被依赖（解锁）、更新时间、简短结果/摘要
- 操作：
  - 打开成员会话
  - 定位任务（如果现有任务列表支持）
- 不做内联编辑；编辑仍走现有任务协议

### 4.5 Leader 收件箱

- 过滤 `messages` 中 recipient 为 Leader、type 非 system 的记录
- 按时间倒序显示最近 5 条
- 显示发送者、类型、摘要、时间；未读状态可用现有 `readBy` 推导
- “查看全部”跳到现有团队活动/消息视图
- 空态：`暂无待处理消息`
- 第一版只读，不在这里审批或回复

## 5. 数据与组件

不新增后端 API；全部从现有 `TeamView`、tasks、messages 派生。

新增：

```text
src/client/team-overview.tsx        总览视图、任务详情、收件箱
src/client/team-overview-data.ts    纯函数：进度、依赖分层、收件箱过滤、默认视图
tests/client-team-overview.spec.ts  SSR/纯函数测试
```

修改：

```text
src/client/team-board.tsx           视图切换、传入 tasks/messages
src/client/TeamBoard.module.css     总览布局、依赖图、收件箱、窄屏

```

不新增依赖，不引入 DAG 画布库。

## 6. 状态与错误

- 团队数据加载中：总览显示骨架/占位，不显示假的 0
- 数据刷新失败：保留上次成功数据，顶部现有错误条
- 任务为空：总览显示“还没有任务，Leader 派发后会出现在这里”
- 收件箱加载失败：只在收件箱区域提示，不影响任务图
- 依赖图无法分层：显示“未分层”并列出循环/缺失依赖，不静默丢弃
- 任务详情目标已删除：显示“任务已移除”，保留列表

## 7. 可访问性

- 视图切换用 `aria-pressed` 按钮，不用纯 div
- 依赖节点是 `<button>`，支持 Tab / Enter / Space
- 选中节点有 `aria-pressed` 或 `aria-current`
- 进度条有文本计数；颜色不是唯一信息
- 任务 chip 的截断标题保留 `title`
- 窄屏不隐藏关键操作

## 8. 测试与验收

纯函数：

- 进度计数覆盖 pending/assigned/running/blocked/completed/failed/cancelled
- 依赖分层：链、分叉、多依赖、循环、缺失依赖
- 默认视图：有 live work 选总览，否则任务
- 收件箱只保留 Leader recipient，排除 system，按时间倒序

客户端：

- 总览/任务切换保留搜索和成员筛选
- 空任务、空依赖、空收件箱都有明确空态
- 选中任务后详情显示 owner/依赖/被依赖
- 窄屏渲染不溢出
- 现有任务看板测试不回归

验证：

```text
npx vitest run tests/client-team-overview.spec.ts
npm run typecheck
npm run build
```

真实截图：至少 1440px 与 390px 两档，检查总览和任务视图。

## 9. 实施顺序

1. 视图切换 + 总览壳 + 进度 + 成员任务 chips（复用现有数据）
2. 依赖分层 + 依赖图 + 选中任务详情
3. Leader 收件箱
4. 响应式与真实截图回归

第一版不做：拖拽节点、缩放、时间线动画、内联编辑、审批/回复收件箱。
