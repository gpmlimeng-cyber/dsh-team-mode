# 全局总览设计

> 2026-10-23 · 只读总览，不做全局 Captain

## 1. 目标

在团队工作台默认页提供一个跨团队、跨助手的只读总览：

- 现在有多少团队/助手在工作
- 哪些需要我处理
- 哪些被阻塞
- 一眼跳到对应团队或助手

这是入口和状态面板，不是控制台。

## 2. 范围

包含：

- 团队：成员、Leader、运行中、待审批、阻塞任务
- 助手实例：状态、运行任务、待输入、主会话入口
- 汇总：运行中 / 需要你 / 阻塞 / 空闲
- 筛选：全部 / 需要我 / 运行中 / 空闲
- 团队和助手点击跳转

不包含：

- 全局 Captain
- 批量操作、跨团队派活
- 全局审批
- 新 API 或新存储
- 助手/团队详情复制

## 3. 数据

复用：

- `team.list` 的 `TeamView`
- `assistant.instance.list` 的 `AssistantInstanceView`
- `assistant.task.list` 的助手任务

只读；不写入团队、助手、任务或 Session。

## 4. 汇总规则

- 运行中：团队 `isTeamExecuting` 或助手实例 `status === 'active'` 或有 running task
- 需要你：团队成员 `waiting_approval` > 0，或助手任务 `needs_input`
- 阻塞：团队有 blocked 任务（依赖未完成）；助手任务 `queued` 且未运行不计
- 空闲：不在以上三类
- 一个条目可以同时“运行中”和“需要你”；筛选时以更需注意的状态优先

## 5. 界面

工作台默认页顶部：

```text
全局总览
3 个团队 · 4 个助手
[运行中 2] [需要你 1] [阻塞 1] [空闲 3]

需要你
  软件研发团队    2 个待审批    →
  论文助手        1 个待输入    →

[全部] [需要我] [运行中] [空闲]

团队
  ...
助手
  ...
```

- 团队行：名称、Leader、成员数、进度、状态
- 助手行：名称、模型、状态、任务数、主会话入口
- 空态按筛选区分
- 无主会话的助手显示“未创建主会话”，不强行 ensure
- 320px 单列，筛选横向滚动或换行，不截断关键数字

## 6. 不做的判断

- 不在总览里直接审批
- 不在总览里创建任务
- 不在总览里停/删团队
- 不做跨团队拖拽
- 不做全局未读消息中心

## 7. 验收

- 汇总数字与团队/助手实际状态一致
- 需要你优先展示
- 筛选不产生假计数
- 事件更新后刷新，不要求手动刷新
- 无新增 API
- 320px 可用
