# 本地单机同事体验 — 五项规划

> 2026-10-28 · 借鉴 OpenBot 的“同事主页、行动轨迹、接管、能力/审批、一键创建”，
> 但只做 DSH 本地单机，不做容器/云端/多租户。
> 逐项与产品负责人对齐后，再进入实现。

## 总原则

```text
不新增第二套聊天
不新增第二套权限系统
不记录完整 transcript
每个功能先回答一个用户问题
```

五项分别回答：

```text
P0 同事主页    这个同事现在在干嘛？
P1 行动轨迹    它刚刚做了什么，凭什么信？
P2 接管        它卡住了，我怎么接手？
P3 能力/审批   它能做什么，哪些要问我？
P4 一键创建    我怎么快速得到一个同事？
```

## 已对齐结论（2026-10-28）

```text
P0 放置：现有助手详情顶部加摘要块
P0 密度：状态 + 当前 + 最近 + 三个动作
P1 粒度：任务 + 文件 + 测试，不做工具原始输出
P2 方式：暂停 + 人工在会话操作 + 恢复
P3 深度：只读摘要 + 跳现有设置
P4 预设：5 个固定角色（研究员/审查员/实现者/测试员/协调者）
```

后续实现按此为准，不再重复对齐这五项；如要改，单独提出。

## P0 · 同事主页

### 用户问题

```text
打开一个助手，不想先看设置表单
先知道：在等什么、在做什么、最近怎么样
```

### 放置

```text
现有助手详情（sidebar.right.pane.tab）
首屏摘要，下面是现有设置
不新增侧栏入口、不新增页面
```

### 首屏内容

```text
身份
  name / title / blurb
状态
  空闲 / 进行中 / 等待你确认
当前
  当前任务或线程（一条）
最近
  最近一次动作（一条）
动作
  打开会话 / 新任务 / 编辑设置
```

### 数据

```text
AssistantInstance
assistant.task.list
pending decisions / unread
sessions.list 投影
```

### 不做

```text
不展示完整消息历史
不展示工具原始日志
不做头像大卡
```

### 验收

```text
不看设置也能回答“它在等什么/在做什么”
一条动作可直达会话或任务
无新接口
```

### 待对齐

```text
A. 替换现有设置首屏
B. 现有详情顶部加摘要块
C. 右侧栏新增“概览”tab
```

## P0.5 · 永久同事 Chat（必做）

> 用户已确认：这不是等行为证明的选项，是必须做的功能。
> 行为数据只决定“是否强制改写 /new”，不决定要不要做永久 Chat。

### 用户问题

```text
点开同事，应该回到同一个关系
而不是又开一段临时会话
```

### 必做基线

```text
每个助手有且只有一个主会话（mainSessionId）
  → 作为同事关系会话

点助手行
  → 永远打开主会话
  → 不存在则创建

主会话标记
  → 固定 / 置顶 / “同事对话”标签

新开对话
  → 创建 scratch 会话
  → 不替换、不拆掉主会话

压缩
  → 主会话可压缩上下文
  → 会话 ID / 历史关系不变

归档主会话
  → 显式操作
  → 下一次点同事创建新的关系会话
```

### `/new` 改写

```text
如果宿主提供命令拦截/压缩接口：
  主会话里的 /new → /compact
  普通 scratch 会话保留 /new

如果宿主没有命令拦截：
  不改写 /new
  提供显式“压缩上下文”和“开始新关系”
  并在文案里说明：/new 会开临时会话，不拆主关系
```

### 数据

```text
AssistantInstance.mainSessionId
session 标题/固定标记
DSH 命令/压缩接口（需审计）
```

### 验收

```text
点同事 → 主会话
7 天内回访同一主会话
主会话被压缩后仍可继续
scratch 会话仍可访问
不丢历史
```

### 待对齐

```text
A. 主会话只做入口固定，不改 /new
B. 宿主支持则改写 /new，不支持则显式按钮
C. 完全强制：/new 一律变 /compact
```

```text

```


## 推荐顺序

```text
P0 同事主页
P0.5 永久同事 Chat
P3 能力/审批分栏
P4 一键创建
P1 行动轨迹
P2 接管（等本地浏览器）
```

理由：

```text
P0/P0.5 先让“点同事”成为一段关系
P3 用现有数据，提升“同事感”
P4 降低创建成本
P1 需要定义证据粒度
P2 依赖本地电脑能力
```

## 与现有队列的关系

```text
identity 助手 title/blurb 是 P0/P4 的前置
Team Run 总览 是 P1 的团队侧
通知/归档 已解决“哪里需要我”
```
