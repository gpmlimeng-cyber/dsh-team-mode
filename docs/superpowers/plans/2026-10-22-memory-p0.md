# Memory P0 Implementation Plan

> **For agentic workers:** use the AgentTeams plan. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add the structured memory foundation for assistants and teams: visibility, revisions, team proposals/acceptance, and scoped prompt injection. No UI, auto-capture, or context compaction.

**Architecture:** Store `MemoryEntry[]` inside the existing `assistant_memory` record and the team aggregate to avoid a domain version bump. Assistant entries are private by default; team entries are proposed by members and accepted by the Leader. Active team memory is injected only into team member prompts.

**Tech Stack:** TypeScript, Zod, Cordis, Vitest.

**Spec:** `docs/MEMORY-ARCHITECTURE.md`, `docs/DECISIONS-IDENTITY-MEMORY.md`.

## Global Constraints

- No domain/schema version bump and no data migration.
- Legacy `assistant_memory.content` and teams without memory load unchanged.
- No memory UI, auto-capture, auto-recall, or context compaction.
- Assistant memory is read-only in worker sessions.
- Team memory does not enter DM or another team.
- `npm run check` must pass.

## Review Focus

- Legacy assistant/team rows parse and behave unchanged.
- Visibility filtering: private never enters team; proposed never loads.
- Revision conflict is rejected, not last-write-wins.
- Members cannot accept their own proposals; Leader-only accept.
- Reset/archive cannot orphan or broaden memory.
- No cross-team reads/writes.
