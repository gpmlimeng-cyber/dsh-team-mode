# 对齐 OpenMausBot：从基础重建的分层计划

> 2026-10-29 · 目标：在本插件里做到**产品面完全对齐 OpenMausBot**，从基础层往上重建，而不是继续点状补按钮。

## 0. 先把「完全复刻」定义清楚

OpenMausBot 有 **1374 个 TS/TSX 文件、319 个组件、32 个状态切片**，并且是 Electron 应用：主进程自己起 Claude/Codex CLI、自己管云电脑、自己接支付与账号。逐行复刻既不可能也没必要。因此定义三层对齐：

| 层 | 是否完全对齐 | 说明 |
|---|---|---|
| **交互与信息架构** | ✅ 完全对齐 | 侧栏结构、会话/线程、房间、任务、审批、例行、通知、设置的入口位置与行为逐项一致 |
| **数据模型与语义** | ✅ 完全对齐 | 同一实体同一字段同一状态机（含"审批有等级""例行三态""记忆中 proposed/superseded"） |
| **底层实现** | ❌ 不复制 | 宿主（DSH）已提供：Agent 运行时、模型路由、会话持久化、权限闸门、workspace。我们只在插件 API 内等价实现 |
| **外壳/商业** | ❌ 不复制 | Electron 壳、CLI 子进程、云电脑、支付、账号体系、手机端 |

一句话：**形与义照抄，骨换宿主的。**

## 1. 现在的差距（事实清单）

| 面积 | OpenMausBot | 我们 | 差距 |
|---|---|---|---|
| 助手（bot） | 侧栏一排"联系人"，每个有形象/模型/云电脑/应用 | 已有（助手 = 同事实例） | 缺"云电脑/应用"那层 |
| 会话 | 线程 + 消息 + steer/queue + 附件 + 语音 | 有线程与消息 | **缺 steer（边跑边改）**、附件、语音 |
| 团队/房间 | rooms、people、team chats、共享 | 有团队/成员/公告/收藏 | 缺 people 视图、房间共享 |
| 任务与活动 | 任务板 + 活动时间线 + checkpoint | 有任务/目标/检查点 | 缺独立活动面（已并入任务详情） |
| 审批 | **审批等级**、审批卡、硬清单、作废/超时 | 有 escalation（3 类） | **缺等级**与超时语义（spec 已有） |
| 例行 | routines：定时/webhook、三态、运行记录 | 无 | **整块缺失** |
| 通知 | notification feed、proactivity | 无 | **整块缺失** |
| 记忆 | memory + 摘要 + journal | 有结构化记忆 | 缺自动捕获/摘要（spec 已有） |
| 技能 | skills 存取、SKILL.md 安装 | 有 allowlist | 缺"从任务提炼技能" |
| 连接应用 | Composio/HighLevel 等连接器 | 有 MCP 服务器 | 缺"连接器"抽象 |
| 上手指引 | onboarding 流程 | 只有首用卡 | 缺完整引导 |

## 2. 分层计划（从基础往上）

每个阶段 **schema → service → transport → UI → 一条端到端场景 → 文档**，前一阶段不收口不开下一阶段。

### S0 基础契约（本次先做）

```
定名与关系：Bot / Thread / Message / Room(Team) / Member / Task / Approval / Routine / Skill / App
统一 ID 与时间语义（epoch ms + ISO 的边界写清）
统一状态机命名（open/lifted、active/proposed/superseded、on/paused/auto_paused）
事件词汇表（created/updated/archived/…）与订阅契约
```

Exit：一份 `docs/parity/00-domain.md`，所有后续模块直接用这套词，不再各自造名。

### S1 存储与运行时骨架

```
store 表清单 + 迁移策略（只加可选字段，不升 schemaVersion 之外的东西）
传输边界：哪些走 transport、哪些走 host 服务
事件派发与订阅（含同毫秒排序、单调序号）
```

Exit：`docs/parity/01-storage.md` + 迁移兼容测试（旧数据可读、新字段可选）。

### S2 会话面（用户 80% 时间在这里）

```
侧栏 bot 列表 → 线程列表 → 消息流 → composer
steer vs queue（运行中能否改方向）
审批卡在消息流内（不是设置页）
附件、@提及、停止/重试
```

Exit：一条端到端场景——开一个 bot，发一句，中途 steer，触发一次审批并在流内批准。

### S3 协作面

```
team/room 成员与 people 视图
任务板 + 检查点 + 活动时间线
mention / 分派 / 交接
```

Exit：三人团队从建团到任务完成，全程在 UI 内可追踪。

### S4 主动面（本轮 spec 已写，未实现）

```
routines：定时与触发、三态、运行记录（今日简报是本层的第一条）
notifications feed：待确认 / 未读 / 卡住
escalation 生命周期：过期标记 + 同类记住答案
```

Exit：不开 DSH 三天，回来能看见"这三天发生了什么、现在要我做什么"。

### S5 记忆与技能

```
记忆四条链（写入分级见 2026-10-27-memory-gaps 附录）
技能：从完成任务提炼、安装 SKILL.md、来源与使用次数
上下文裁剪阈值
```

Exit：同一任务第二次执行时，模型能复用上次技能与记忆。

### S6 集成面

```
连接器抽象（当前 MCP 是其中一种）
团队/房间导出与共享（已有基础）
组织与多工作区边界
```

### S7 治理与发布

```
用量、诊断、i18n、打包
```

## 3. 每阶段的对产标准（不许"感觉像了"）

每个模块收口时产出 `docs/parity/<module>.md`：

```markdown
| OpenMausBot 组件/行为 | 我们的实现 | 一致性 | 证据 |
| BotContextMenu         | …          | 完全/等价/不做 | 截图 + 测试名 |
```

**"等价"必须写清等价在哪**（例：OMB 的云电脑 → 我们的宿主 workspace，因为宿主不提供远程机）。**"不做"必须写理由**，否则下个季度会有人重问。

## 4. 明确不复制

| 不复制 | 理由 |
|---|---|
| Electron 壳与桌面集成 | 我们跑在 DSH Web GUI 里，壳是宿主的 |
| CLI 子进程（claude/codex） | 宿主已有 Agent 运行时与模型路由，重复造会打架 |
| 云电脑 / VPS / 手机端 | 宿主与产品边界不提供，等价物是 workspace |
| 支付、账号、企业版 | 不属于插件职责 |
| 语音模式 | 宿主无音频通道，等宿主提供 |

## 5. 执行方式

- **一次一个阶段**，阶段内一次一个模块（路线图已有同名规则）；
- 每阶段开工前先做**盘点**（像 M1 那样带 `文件:行号` 的现状表），不做凭印象的实现；
- 每个实现任务都要有**一条端到端场景**，不是若干单元断言拼接；
- 队长自己验收：读 diff、跑 `npm run check`、看 parity 表。
